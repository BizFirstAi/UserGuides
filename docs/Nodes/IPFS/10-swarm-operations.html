Swarm Operations

resource: swarm — 5 operations for peer connectivity and addresses

peers

Lists the node's currently connected peers.

FieldTypeRequiredDefaultDescription
verboseboolNoKubo default (false)Include extra per-peer detail (multiplexer, etc.). Unset lets Kubo decide.
streamsboolNoKubo default (false)Include each peer's open libp2p protocol streams.
latencyboolNoKubo default (false)Include measured round-trip latency per peer.
directionboolNoKubo default (false)Include connection direction (inbound/outbound) per peer.
identifyboolNoKubo default (false)Run the libp2p identify protocol per peer and include its result.

List-shaped response: array of peer entries plus count.

connect

FieldTypeRequiredDescription
peerAddresstext✓ YesThe peer's full multiaddr, e.g. /ip4/1.2.3.4/tcp/4001/p2p/QmPeerId... — must include /p2p/<PeerID>.

Missing → CFG_MISSING_PEER_ADDRESS.

disconnect

FieldTypeRequiredDescription
peerAddresstext✓ YesThe peer multiaddr, or bare /p2p/<PeerID>, to disconnect from.

Missing → CFG_MISSING_PEER_ADDRESS.

addrs

Lists known addresses per connected peer. Takes no feature-specific fields beyond the standard Kubo connection config.

addrsLocal

Lists this node's own local listening addresses.

FieldTypeRequiredDefaultDescription
idboolNoKubo default (true)Append this node's own Peer ID (/p2p/<PeerID>) to each address.
addrs vs. addrsLocal: addrs reports what addresses your daemon has observed for other peers; addrsLocal reports what addresses your own daemon is listening on. Use addrsLocal when you need to hand your own node's address to someone else for a connect call.
