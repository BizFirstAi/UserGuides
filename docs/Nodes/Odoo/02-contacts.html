Contacts

Generic CRUD against res.partner — people, companies, and addresses in one table

resource: contact — model res.partner. Companies, individual people, and delivery/invoice addresses all live in this one Odoo table, distinguished by the is_company and parent_id fields rather than by separate models.

The Writable Field Picker

The fields input is schema-driven: the node calls Odoo's fields_get for res.partner against your connected instance and shows every field that is not read-only and not a relational set (one2many/many2many) — matching the exact rule n8n's own Odoo node uses. Because this is discovered at runtime, custom fields added via Odoo Studio, and version-specific differences (e.g. mobile and title existing on Odoo 18 but not 19), show up automatically without a node update.

many2many Fields — Add, Don't Replace

Relational-set fields such as category_id (contact tags) are excluded from the plain field picker but remain writable through relationFields, modeled as intent rather than raw Odoo command syntax:

{
  "category_id": { "mode": "add", "ids": [3, 5] }
}

Four modes are available: add (default — adds IDs, preserves everything already set), remove, replace (discards every value not listed — destructive, chosen deliberately), and clear. add is the default specifically because it is the non-destructive choice — reaching for replace when you meant "add one tag" silently deletes every other tag on the contact, and Odoo reports success either way.

Relation Fields on Read

Fields like country_id, parent_id, and user_id come back normalized as { "id": 12, "displayName": "United States" } rather than Odoo's raw [id, "name"] tuple — one consistent shape for every relation on every model, everywhere this node emits data.

Filtering with getMany

The domain input builds an Odoo search domain from field/operator/value conditions, with AND/OR grouping — see Input & Output for the full filter shape. A common contact filter:

{
  "topLevelOperator": "and",
  "groups": [
    { "operator": "and", "conditions": [
      { "field": "is_company", "operator": "=", "value": true },
      { "field": "country_id.code", "operator": "=", "value": "US" }
    ]}
  ]
}

Field paths may traverse relations with dot notation (country_id.code) — Odoo resolves these server-side.
