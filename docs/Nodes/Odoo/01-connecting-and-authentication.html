Connecting & Authentication

Two transports, one credential shape — and one critical difference in how each reports failure

Credential Fields

DatabasedatabaseSee Database Name below — set this explicitly for self-hosted instances.

Auth Mode 1 — API Key Recommended

Calls POST {siteUrl}/json/2/{model}/{method}. Requires Odoo 19 or later.

Real HTTP errors. A failed call on this transport returns a genuine 4xx/5xx status — 401 for a bad key, 403 for an access error, 404 for an unknown model. Failure detection is straightforward and the retry handler can act on the status code directly.

Auth Mode 2 — Username / Password (Legacy)

Calls POST {siteUrl}/jsonrpc — common.login to obtain a uid, then object.execute for every subsequent call. Works on every currently-supported Odoo version.

Deprecated. Scheduled for removal in Odoo 22 (fall 2028) and Odoo Online 21.1 (winter 2027). Use API Key if your instance supports it.
Errors on this transport arrive as HTTP 200. The legacy JSON-RPC endpoint wraps application faults — AccessError, ValidationError, an unknown model — inside a JSON-RPC error envelope in a successful HTTP response. The node inspects the response body for an error payload on every call rather than trusting the status code; you never have to handle this yourself, but it explains why the HTTP status alone is not a reliable signal if you're diagnosing a raw network capture. See Troubleshooting.

The legacy transport also caches the logged-in uid per credential (default 30 minutes) so a 100-item batch operation costs 101 requests instead of 300 — Odoo's uid does not expire mid-session the way an OAuth token does, and the cache is invalidated immediately on a 401/403.

Database Name

Effectively required for self-hosted instances. If left blank, the node derives it from the site URL's hostname — taking the first dot-segment, which correctly yields my-org for my-org.odoo.com but produces nonsense for anything else: 10 for http://10.0.0.5:8069, or localhost for a local instance. If you're pointing at a self-hosted Community or Enterprise install, set Database explicitly.

Tunables

These are set at the platform level (the Odoo configuration section), not per-credential — ask your administrator if you need one changed:

SettingDefaultPurpose
Timeout30sPer-request timeout.
Max Retries3Retries for transient transport faults (502/503/504, socket failures, and 429 on the chance the instance sits behind a throttling proxy) with exponential backoff — 1s, 2s, 4s at the default. Application faults (AccessError, ValidationError) are never retried; they'd fail identically every time.

Testing the Connection

Use any read-only operation with a small limit as a connectivity check — for example resource: lookup, model stage, with limit: 1. A successful response confirms the site URL, database, and credential are all correct without touching any real data.
