Lookup Tables

Read-only access to the CRM configuration tables workflows need for ID/name mapping

resource: lookup — eight CRM configuration tables, each addressed by a short resource key rather than the raw Odoo model name.
Read-only by design, not by accident. Creating pipeline stages, sales teams, tags, lost reasons, or UTM values is a CRM configuration task performed in Odoo directly, not a workflow data operation — exposing writes here would let a workflow silently reshape a company's CRM taxonomy. This service exposes no write path at all; it isn't just omitted from a routing table. If you genuinely need to write one of these tables, use Custom Resource with the model name below.

Available Lookups

Resource KeyOdoo ModelDefault Fields
activityTypemail.activity.typeid, name, summary, delay_count, delay_unit, icon, category
stagecrm.stageid, name, sequence, is_won, fold, team_ids
teamcrm.teamid, name, active, company_id, member_ids
tagcrm.tagid, name, color
lostReasoncrm.lost.reasonid, name, active
utmSourceutm.sourceid, name
utmMediumutm.mediumid, name, active
utmCampaignutm.campaignid, name, title, user_id, stage_id, tag_ids

Pass fieldsList to override the default projection for any lookup — the defaults exist so a common "build an ID → name map" call doesn't fetch every field on the model, not because other fields are unavailable.

Why stage Includes is_won and sequence

These two fields are what actually make pipeline-stage data usable in a workflow: is_won identifies the "won" stage portably (stage IDs and names vary per pipeline configuration, so you can't hardcode "Won" as a stage name), and sequence is the only reliable way to tell forward pipeline movement from backward.

Typical Use

Fetch stage or team once at the start of a workflow to build an ID/name map, then reference those IDs when creating or filtering Leads — for example, resolving a human-entered team name to the teamID that Convert expects.
