Leads & Opportunities

CRUD on crm.lead, plus the four pipeline actions n8n's Odoo node doesn't have

resource: lead — model crm.lead. Leads and opportunities share one unified model, distinguished by the type field (lead or opportunity). Every query must filter on type or it processes both at once.

Plain CRUD

Create, Get, Get Many, Update, and Delete work exactly as they do for Contacts — schema-driven field picker via fields / fieldsList, filterable with domain on Get Many. See Input & Output for the shared config-key pattern.

Pipeline Actions

Not in n8n's Odoo node. These four actions are CRM pipeline behavior, not plain field writes — they call real Odoo server methods (convert_opportunity, action_set_won, action_set_lost, message_post) rather than setting fields directly.
OperationConfig KeysWhat Happens
convert leadID, optional partnerID, userID, teamID Promotes a lead to an opportunity, optionally assigning the linked contact, salesperson, and sales team in the same call.
markWon leadID Moves to the nearest is_won stage in the lead's own pipeline and sets probability to 100. Takes no other parameters — Odoo picks the target stage itself.
markLost leadID, optional lostReasonID Archives the opportunity and zeroes probability. The record then falls out of default Get Many results (Odoo's active-record filter) — an explicit active in [true, false] domain condition brings it back.
logNote leadID, noteBody Posts an internal chatter note (not a customer-facing message — no followers are emailed). Returns the new message's ID, not a boolean.

Convert Is Not Always What It Looks Like

Odoo's convert_opportunity silently skips already-won or already-lost leads and still returns true. This node pre-reads the record before calling it, so it can tell the difference. If the lead is already archived (lost) or already won, the operation reports success with applied: false and a warning explaining why — never a false "converted" result. Check applied, not just success, when branching a workflow on whether a conversion actually happened.

Log Note Returns an ID, Not a Boolean

Unlike Convert/Mark Won/Mark Lost, logNote doesn't report an applied flag — Odoo's message_post returns the newly created mail.message record itself, which this node unwraps to a plain messageID in the output. Use that ID if a later step needs to reference the specific chatter entry.
