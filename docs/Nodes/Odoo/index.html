Odoo

CRM automation against self-hosted or Odoo.com instances — contacts, leads/opportunities, activities, any custom model, and a change-polling trigger

Integration layer status: the JSON-RPC/JSON-2 transport, credential handling, and all six resource services (Contact CRUD, Lead actions, Activity scheduling, Custom Resource CRUD, read-only Lookup tables, and the polling Trigger) are fully implemented and covered by this guide. The workflow-node wiring that exposes these as a configurable node inside Flow Studio is still being built — see Roadmap for what's shipped versus what's next.
What it does: The Odoo node talks to any Odoo 15+ instance (self-hosted Community/ Enterprise or Odoo.com) over its JSON-RPC or JSON-2 API. It covers the CRM surface most workflow automation needs — contacts, leads, opportunities, activities — plus a Custom Resource escape hatch for any other installed model, and a change-polling trigger so a workflow can react to new or updated records without a webhook.

Quick Start

  1. Add an Odoo node to your workflow and attach a credential (API Key for Odoo 19+, or Username/Password for older/legacy instances — see Connecting & Authentication)
  2. Set resource to contact and operation to create
  3. Fill in fields with at least a name — the schema-driven field picker shows every writable field on res.partner for the connected instance
  4. Run the workflow — the node returns the new contact's record ID
Beyond n8n's Odoo node: the four CRM pipeline actions on Leads — Convert to Opportunity, Mark Won, Mark Lost, and Log Note — are not available in n8n's Odoo node at all. See Leads & Opportunities.

Core Concepts

Resources

Operations are grouped by resource, matching the platform's resource / operation config-key convention used by every shipped node:

  • contact — res.partner: people, companies, and addresses in one table, distinguished by is_company / parent_id
  • lead — crm.lead: leads and opportunities in one unified model, distinguished by type
  • activity — mail.activity: scheduled to-dos attached to any record via res_model_id + res_id
  • customResource — any other installed model, addressed by name
  • lookup — eight read-only CRM configuration tables, for ID/name mapping in a workflow
  • trigger — polls a chosen target resource for changed records

Two Transports, One Node

Odoo exposes three external APIs; this node implements the two that matter today — the current JSON-2 endpoint (API Key, Odoo 19+) and the legacy JSON-RPC endpoint (Username/Password, every supported version but scheduled for removal). Classic XML-RPC is deliberately not implemented — same deprecation timeline as JSON-RPC, none of the upside. See Connecting & Authentication for the practical differences, especially around error detection.

Schema-Driven, Not Hardcoded

Odoo has no static field catalogue — a model's shape genuinely varies between instances and versions (res.partner dropped mobile and title in 19.0). Every writable-field picker is built at runtime from Odoo's own fields_get, cached per credential and model for 6 hours by default.

Services Never Throw

Every protocol, network, or Odoo-reported fault comes back as a failed result carrying a stable error code from a fixed set — never an unhandled exception. Only cancellation propagates as an exception. See Troubleshooting for the full code list.
