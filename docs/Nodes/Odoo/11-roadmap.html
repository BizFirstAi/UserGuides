Roadmap

What's shipped, what's next, and the one production caveat worth planning around

✅ Shipped

  • Transport layer for both JSON-2 (API Key, Odoo 19+) and legacy JSON-RPC (Username/Password), including exponential-backoff retry on transient faults and correct fault detection on both (including the legacy transport's HTTP-200-with-error-envelope behavior)
  • Generic CRUD service shared by Contacts, Leads (plain fields), and Custom Resource
  • Lead pipeline actions: Convert, Mark Won, Mark Lost, Log Note — including the pre-read that makes Convert's success/applied distinction honest
  • Activity scheduling and completion, including the res_model → res_model_id two-step resolution and its permanent per-credential cache
  • Eight read-only Lookup tables with sensible default field projections
  • Schema service — runtime fields_get discovery, cached 6 hours, driving the writable-field picker
  • Polling Trigger with watermark + seen-ID exactly-once semantics, first-cycle seeding, and failure-holds-cursor behavior
  • Full domain-filter builder (AND/OR groups, ten operators, relation dot-paths, negation)
  • many2many relation-command writes (add/remove/replace/clear) via relationFields

🚧 Next — Workflow Node Wiring

The Domain and Services layers documented in this guide are complete and independently usable. What's still ahead is the OperationInfo/executor layer that exposes them as a configurable node inside Flow Studio — the config-key contracts documented in Input & Output are already defined and stable, so this is wiring work rather than design work.

⚠️ Production Requirement — Persistent Trigger State

The Trigger's cursor is stored via the platform's distributed cache abstraction. The default in-memory provider does not survive a process restart — deployments that need the trigger to be complete (not just "usually works") must configure a persistent provider (Redis or SQL Server) before relying on it in production. See Trigger / Polling.

Deliberately Out of Scope

  • Classic XML-RPC transport — same deprecation timeline as legacy JSON-RPC, none of the upside
  • Writes to the eight Lookup tables — CRM configuration is an Odoo-side task, not a workflow data operation; use Custom Resource if you genuinely need to write one
  • A second permission layer on top of Odoo's own user permissions for Custom Resource — model-name validation is a syntax check only
