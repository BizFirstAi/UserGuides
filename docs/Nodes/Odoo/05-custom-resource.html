Custom Resource

Generic CRUD against any installed Odoo model — the escape hatch for everything this node doesn't name explicitly

resource: customResource — you supply the Odoo model name yourself (e.g. sale.order, product.product, project.task). Under the hood this calls the exact same generic CRUD service that Contacts and the plain-CRUD side of Leads use — there is no behavioral difference except that you name the model.

Model Name Validation

The model field must match ^[a-z][a-z0-9_.]*$ — lowercase, starting with a letter, dots and underscores allowed (Odoo's own naming convention: sale.order, project.task). This is checked client-side before any network call, failing fast with ODOO_INVALID_MODEL_NAME.

This is a syntax check, not an authorization check. It does not stop a workflow from targeting a sensitive model like res.users. What a given Odoo user is actually allowed to read or write is enforced by that user's own Odoo permissions — the node does not add a second permission layer on top.

Schema-Driven Field Picker, Any Model

Exactly as with Contacts, the writable-field picker is built at runtime from Odoo's fields_get for whatever model you name, cached per credential+model for 6 hours. This is what makes Custom Resource genuinely general — there's no hardcoded field list to fall out of date as your Odoo instance's custom fields and installed modules change.

When to Use Contact/Lead/Activity Instead

Use the named resources when they cover your case — they carry the specialized behavior (Lead's pipeline actions, Activity's model-ID resolution and mark-done semantics) that Custom Resource intentionally does not duplicate. Reach for Custom Resource for everything else: sales orders, inventory, projects, or any module-specific model your Odoo instance has installed.

Operations

Same five as every other CRUD resource — create, get, getMany, update, delete — using model plus the same recordID/fields/fieldsList/domain keys documented in Input & Output.
