Activities

Scheduled to-dos attached to any record — Calls, Meetings, Emails, To-Dos

resource: activity — model mail.activity. Activities attach to any record on any model via res_model_id + res_id — a follow-up call on a Contact, a meeting on a Lead, anything with the mail.activity.mixin installed.

Operations

OperationConfig KeysNotes
create resModel, resID, activityTypeID, plus optional fields Schedules the activity. See the two-step resolution below.
get / getManyactivityID, or resModelFilter / resIDFilter to list all activities on one recordPlain CRUD via the shared Custom Resource path.
markDone activityID, optional feedback Completes the activity. See below — the record is usually gone afterwards.
deleteactivityIDRemoves the activity without completing it.

Why Create Is a Two-Step Operation

Odoo's activity read returns a human-readable res_model string (e.g. "crm.lead") — but write ignores that field entirely and requires the integer res_model_id, a foreign key into Odoo's own ir.model registry. So every Create first resolves the target model name to its ir.model row ID, then creates the activity with that resolved ID. This mapping never changes within an instance's lifetime, so it's cached permanently per credential — scheduling follow-ups for 100 leads resolves crm.lead once, not 100 times.

If the target app isn't installed, resolution fails with ODOO_MODEL_NOT_FOUND — "Linked document model "x.y" was not found in this Odoo instance. Confirm the owning application is installed." This will fail identically for every record against that model, so it's worth checking first rather than retrying.

Mark Done — the Record Is Usually Gone Afterwards

Completing an activity (markDone, Odoo's action_feedback) posts the optional feedback to the target record's chatter, then archives or deletes the activity. A subsequent Get on that activityID returning not-found is the expected outcome, not an error — don't build a workflow that reads an activity back immediately after marking it done.

Filtering Activities by Target Record

Use resModelFilter + resIDFilter on Get Many as a shortcut for "every activity on this specific record" — the node combines them into the correct domain automatically rather than you needing to hand-build a two-condition filter.
