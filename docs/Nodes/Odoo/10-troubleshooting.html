Troubleshooting

Every stable error code this node emits, and what actually causes each one

"It works sometimes, but I don't see the error"

On the legacy Username/Password transport, application faults arrive as HTTP 200. AccessError, ValidationError, and similar faults are wrapped inside a JSON-RPC error envelope in a technically-successful HTTP response — the node inspects the payload for you, so within the node this is transparent, but if you're capturing raw traffic to diagnose something, don't trust the HTTP status alone on this transport. See Connecting & Authentication.

"Convert reported success but nothing changed"

Check applied in the result, not just success. Odoo's convert_opportunity silently no-ops on a lead that's already won or already archived (lost) and still returns true — this node surfaces that as success: true, applied: false with a warning, rather than reporting a conversion that didn't happen. See Leads & Opportunities.

"A field I know exists isn't in the picker"

The writable-field picker excludes read-only fields and relational sets (one2many/many2many) by design — that's what makes it safe to auto-generate. For many2many fields specifically, use relationFields instead (see Contacts). If a field is genuinely missing and shouldn't be, remember schema is cached for 6 hours per credential+model — a field added via Odoo Studio moments ago may not show up until the cache expires.

"My trigger stopped firing after a deploy/restart"

If the platform's distributed cache is running on the in-memory provider rather than a persistent one (Redis, SQL Server), the trigger's cursor is lost on restart and silently reseeds at "now" — every change made before the restart is skipped, with no error. See Trigger / Polling and Roadmap.

"Get Many returns fewer records than I expect"

Odoo's active-record filter excludes active = false rows from every default search — most visibly, leads marked lost (which are archived). Add an explicit active in [true, false] condition to your domain to include them.
