Token Operations

resource: token — getInfo and getBalances for Hedera Token Service (HTS) tokens.

What is HTS? The Hedera Token Service lets anyone create fungible or non-fungible tokens natively on the Hedera ledger — no smart contract required. These operations read HTS token metadata and account holdings through the Mirror Node, the same way the account operations read HBAR balances.

token.getInfo

Returns metadata for a single HTS token — its name, symbol, decimal precision, total supply, type, and treasury account.

FieldRequiredDescription
tokenIdRequiredHTS token ID in native form, e.g. 0.0.456858.

Example Request

{
  "resource": "token",
  "operation": "getInfo",
  "network": "testnet",
  "tokenId": "0.0.456858"
}

Example Response

{
  "tokenId": "0.0.456858",
  "name": "Widget Token",
  "symbol": "WDG",
  "decimals": 2,
  "totalSupply": 100000000,
  "type": "FUNGIBLE_COMMON",
  "treasuryAccountId": "0.0.456800",
  "deleted": false,
  "network": "testnet"
}

Field Reference

FieldMeaning
decimalsNumber of decimal places the token's raw integer balance is divided by for display. A raw balance of 100000000 with decimals: 2 displays as 1000000.00.
totalSupplyTotal raw (undivided) supply currently in circulation for the token, subject to the same decimals scaling.
typeFUNGIBLE_COMMON for interchangeable tokens (currencies, points, shares) or NON_FUNGIBLE_UNIQUE for NFTs, where each serial number is a distinct asset.
treasuryAccountIdThe Hedera account that holds the token's un-distributed supply and receives newly minted units. Distinct from any individual holder's account.
deletedtrue if the token has been deleted on the ledger and can no longer be transferred or minted.

token.getBalances

Returns the HTS token holdings for a given account — every token the account holds a balance of, one row per token.

FieldRequiredDescription
accountIdRequiredHedera account ID to list token balances for, e.g. 0.0.1234567.
limitOptionalMaximum number of token balances to return. Range 1–100, default 25.

Example Request

{
  "resource": "token",
  "operation": "getBalances",
  "network": "testnet",
  "accountId": "0.0.1234567",
  "limit": 10
}

Example Response

{
  "accountId": "0.0.1234567",
  "balances": [
    { "tokenId": "0.0.456858", "balance": 100000000, "decimals": 2 },
    { "tokenId": "0.0.731861", "balance": 500000,    "decimals": 0 }
  ],
  "network": "testnet"
}

Each row includes decimals alongside the raw balance so a downstream node can render a correctly scaled display value without a second lookup. To resolve a token ID to its name and symbol, follow up with token.getInfo for that ID — see the combined pattern in Examples.

Pagination: If an account holds more tokens than limit allows, only the first page is returned. Raise limit up to the maximum of 100 for accounts with many token associations, or plan for multiple calls if you need every token an account holds.
