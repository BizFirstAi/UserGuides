Hedera

Query the Hedera network — account balances, HTS tokens, HCS topic messages, and transaction status — straight from the free Mirror Node REST API. No SDK, no signing credential, no node connection to manage.

What it does: The hedera node lets a BizFirst.Ai workflow read live data from the Hedera public ledger (mainnet, testnet, or previewnet) through the community-run Mirror Node REST API. Every current operation is a free, eventually-consistent read — there is no wallet, private key, or Hedera SDK required to use any operation on this page. The node type name is hedera and it belongs to the Blockchain area of the node catalogue.

How It Works

Every Hedera node configuration is built from three common keys, plus operation-specific fields:

Config keyRequiredDescription
resourceYesOne of account, token, topic, transaction, utility.
operationYesThe action to run against that resource — e.g. getBalance, getInfo, getMessages.
networkNoWhich Hedera network to query — mainnet, testnet, or previewnet. Defaults to the Hedera:DefaultNetwork appsetting (typically testnet).

See Input & Output for the full pattern shared across all operations, and Networks for how network resolution works.

Quick Start

The most common first call is account.getBalance — check the HBAR balance of any account on testnet with a single node configuration:

{
  "resource": "account",
  "operation": "getBalance",
  "network": "testnet",
  "accountId": "0.0.1234567"
}

The node calls the Hedera Testnet Mirror Node's account endpoint and returns a friendly, flattened result:

{
  "accountId": "0.0.1234567",
  "tinybars": 250000000000,
  "hbar": 2500,
  "tokens": [
    { "tokenId": "0.0.456858", "balance": 1000 }
  ],
  "network": "testnet"
}

That's the whole round trip — no credential, no client setup, and no Hedera SDK dependency for this call. See Account Operations for the full field reference, or Examples for realistic workflow patterns built on top of it.

Resources & Operations at a Glance

ResourceOperationSummary
accountgetBalanceHBAR balance (tinybars + formatted) and held tokens.
accountgetInfoAccount metadata — EVM address, memo, auto-renew period, key, deleted flag.
tokengetInfoHTS token metadata — name, symbol, decimals, supply, type, treasury.
tokengetBalancesAn account's token holdings, paginated.
topicgetMessagesHCS topic messages in sequence order, base64-decoded to UTF-8 by default.
transactiongetTransaction status, result, consensus timestamp, charged fee.
utilityconvertUnitsConvert between HBAR and tinybar.
utilityvalidateAddressValidate a Hedera account/address string.
Eventually consistent: The Mirror Node lags a few seconds behind consensus. Don't expect a transaction you just submitted elsewhere to appear instantly in transaction.get — see Troubleshooting.
