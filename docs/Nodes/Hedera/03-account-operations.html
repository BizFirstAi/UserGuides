Account Operations

resource: account — getBalance and getInfo, field by field.

account.getBalance

Returns the HBAR balance of a Hedera account, in both raw tinybars and a human-friendly HBAR amount, plus any HTS tokens the account currently holds.

FieldRequiredDescription
accountIdRequiredHedera account ID in native shard.realm.num form, e.g. 0.0.1234567.

Example Request

{
  "resource": "account",
  "operation": "getBalance",
  "network": "testnet",
  "accountId": "0.0.1234567"
}

Example Response

{
  "accountId": "0.0.1234567",
  "tinybars": 250000000000,
  "hbar": 2500,
  "tokens": [
    { "tokenId": "0.0.456858", "balance": 1000 },
    { "tokenId": "0.0.731861", "balance": 50000 }
  ],
  "network": "testnet"
}

tinybars is the exact ledger value (1 HBAR = 100,000,000 tinybars); hbar is the same balance already divided down for display. tokens lists every HTS token the account holds a non-zero balance of, by token ID and raw balance — pair this with token.getInfo to resolve a token ID to its name, symbol, and decimals.

account.getInfo

Returns account metadata rather than balance — useful for verifying an account exists, inspecting its key, or reading its EVM-compatible address.

FieldRequiredDescription
accountIdRequiredHedera account ID, e.g. 0.0.1234567.

Example Request

{
  "resource": "account",
  "operation": "getInfo",
  "network": "testnet",
  "accountId": "0.0.1234567"
}

Example Response

{
  "accountId": "0.0.1234567",
  "evmAddress": "0x00000000000000000000000000000000012d687",
  "memo": "Treasury account",
  "autoRenewPeriodSeconds": 7776000,
  "key": {
    "type": "ED25519",
    "key": "302a300506032b6570032100c3f8b1..."
  },
  "deleted": false,
  "network": "testnet"
}

Field Reference

FieldMeaning
evmAddressThe 20-byte EVM-compatible address derived for this account (Hedera accounts are addressable from both native 0.0.x IDs and an EVM-style 0x… address). Useful when the same account needs to be referenced from EVM-based tooling or smart contracts.
memoFree-text memo the account owner set on the account itself. Often used to label treasury, escrow, or service accounts.
autoRenewPeriodSecondsHow often (in seconds) the account is auto-renewed by paying its renewal fee from its own balance. If the balance runs out at renewal time the account becomes expired rather than being deleted outright.
keyThe account's cryptographic key description — algorithm type (e.g. ED25519, ECDSA_SECP256K1) and the public key material. This is the key required to authorize transactions from the account; the node never has access to the corresponding private key.
deletedtrue if the account has been deleted on the ledger. A deleted account can still be queried for historical info but can no longer send or receive value.
Read-only, always. Both operations are simple GETs against the Mirror Node — they never touch a private key and cannot modify ledger state. Use account.getBalance for a quick funds check and account.getInfo when you need identity/metadata detail about the account itself.
