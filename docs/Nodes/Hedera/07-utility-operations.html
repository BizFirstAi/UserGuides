Utility Operations

resource: utility — convertUnits and validateAddress. No network call required.

Local only: Unlike every other operation on this node, the utility operations don't call the Mirror Node at all — they're pure local computation. That means they work identically regardless of the configured network, and they're free of any eventual-consistency or rate-limit concerns.

utility.convertUnits

Converts an amount between HBAR and tinybar, Hedera's smallest indivisible unit.

FieldRequiredDescription
amountRequiredThe numeric amount to convert.
fromUnitOptionalhbar or tinybar. Default hbar.
toUnitOptionalhbar or tinybar. Default tinybar.

Conversion Reference

The exchange rate between the two units is fixed by protocol, not by market price — it never changes:

HBARTinybar
1100,000,000
0.550,000,000
0.000000011
2,500250,000,000,000

Example Request

{
  "resource": "utility",
  "operation": "convertUnits",
  "amount": 12.5,
  "fromUnit": "hbar",
  "toUnit": "tinybar"
}

Example Response

{
  "amount": 12.5,
  "fromUnit": "hbar",
  "toUnit": "tinybar",
  "converted": 1250000000
}

utility.validateAddress

Validates that a string is a well-formed Hedera account/address — useful before passing a user-entered value into any other operation's accountId field.

FieldRequiredDescription
addressRequiredThe account/address string to validate.

Example Request

{
  "resource": "utility",
  "operation": "validateAddress",
  "address": "0.0.1234567"
}

Example Response — Valid

{
  "address": "0.0.1234567",
  "valid": true
}

Example Response — Invalid

{
  "address": "not-an-account",
  "valid": false,
  "reason": "Does not match a recognized Hedera address format (native shard.realm.num or EVM address)."
}
Validate, don't assume. validateAddress only checks that the string is well-formed — it does not confirm the account actually exists on the configured network. Follow a successful validation with account.getInfo if you need to confirm the account is real and active before acting on it.
