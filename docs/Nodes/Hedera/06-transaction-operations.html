Transaction Operations

resource: transaction — look up the status and outcome of a submitted transaction.

transaction.get

Looks up a previously-submitted Hedera transaction by ID and returns its consensus status, execution result, consensus timestamp, and the network fee actually charged.

FieldRequiredDescription
transactionIdRequiredThe Hedera transaction ID to look up. Both accepted formats are shown below.

Accepted Transaction ID Formats

Hedera transaction IDs combine the paying account and the exact submission timestamp. This node accepts either the native Hedera SDK format or the dash-separated form used by HashScan and other block explorers:

FormExampleNotes
Native0.0.1@1690000000.000000000Payer account ID, an @, then the valid-start timestamp as seconds.nanoseconds. This is the format returned by the Hedera SDK when a transaction is submitted.
Dash form0.0.1-1690000000-000000000Same components, dash-separated instead of @/.. This is the format most block explorers (including HashScan) display and link to — convenient to paste directly from a URL.

Example Request

{
  "resource": "transaction",
  "operation": "get",
  "network": "testnet",
  "transactionId": "0.0.1234567@1690000000.000000000"
}

Example Response

{
  "transactionId": "0.0.1234567@1690000000.000000000",
  "status": "SUCCESS",
  "result": "SUCCESS",
  "consensusTimestamp": "1690000003.512044000",
  "chargedTxFee": 76540,
  "name": "CRYPTOTRANSFER",
  "memo": "Payout batch #4471",
  "network": "testnet"
}

Field Reference

FieldMeaning
status / resultThe transaction's outcome as recorded at consensus — SUCCESS for a completed transaction, or a Hedera response code such as INSUFFICIENT_ACCOUNT_BALANCE or INVALID_SIGNATURE when it failed. A transaction can reach consensus and still fail its business logic — always check this field rather than assuming a lookup succeeding means the transaction succeeded.
consensusTimestampThe exact moment the network reached consensus on this transaction, distinct from the transactionId's valid-start timestamp (which is when the client submitted it).
chargedTxFeeThe actual network fee charged, in tinybars. Use utility.convertUnits to convert this to HBAR for display.
nameThe Hedera transaction type, e.g. CRYPTOTRANSFER, TOKENMINT, CONSENSUSSUBMITMESSAGE.
memoFree-text memo attached to the transaction at submission time, if any.
Eventual consistency: The Mirror Node typically lags live consensus by a few seconds. A transaction submitted moments ago through some other tool or SDK may return "not found" from transaction.get until the Mirror Node catches up — this is expected, not an error in your configuration. See Troubleshooting for retry guidance.
