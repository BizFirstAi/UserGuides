post/getComments

List the comments on a Facebook post with cursor pagination. The read half of every moderation workflow.

Palette name: Get Facebook Post Comments  ·  Graph call: GET /{postId}/comments  ·  Permissions: pages_read_engagement  ·  Field reference: Post Operations

When to Use

  • Moderation pipeline. Read comments, screen them, then hide or delete what fails. The read half of every moderation workflow.
  • Auto-reply triage. Find comments matching a keyword and answer them with post/comment.
  • Sentiment and volume reporting over a campaign's posts.
  • Support intake. Route comments that look like support requests into a ticketing system.

Configuration

FieldRequiredDescription
resourceRequiredMust be post.
operationRequiredMust be getComments.
pageAccessTokenRequiredPage access token, or a stored credential.
postIdRequiredPost ID in {pageId}_{postId} form. Pass a comment ID to read that comment's replies.
limitOptionalComments per page. Defaults to 25.
afterOptionalCursor from a previous run's nextCursor. Blank fetches the first page.

Fields requested from Graph are fixed: id, message, from, created_time.

Sample Configuration

{
  "resource": "post",
  "operation": "getComments",
  "credentialID": 4021,
  "postId": "1153558217851822_122099306859425226",
  "limit": 25
}

Output

FieldTypeDescription
statusstring"success"
countnumberComments in this page of results. Top level, beside status.
items[0].commentsstringEntire Graph response serialised as JSON text. "[]" when empty.
items[0].nextCursorstringCursor for the next page, or "" when exhausted.
comments is a string, not an array. One item comes back, holding the raw Graph JSON as text — not one item per comment. Parse it before iterating. 
{
  "status": "success",
  "resource": "post",
  "operation": "getComments",
  "count": 1,
  "items": [
    {
      "comments": "{\"data\":[{\"id\":\"122099783774252226_966580579776255\",\"message\":\"QA test comment\",\"created_time\":\"2026-08-03T11:31:17+0000\"}],\"paging\":{\"cursors\":{\"after\":\"WTI5...\"}}}",
      "nextCursor": "WTI5..."
    }
  ]
}

Parsing into workable rows

const raw    = $input.items[0].comments;
const parsed = JSON.parse(raw);

return parsed.data.map(c => ({
  commentId:   c.id,
  message:     c.message ?? "",
  authorName:  c.from?.name ?? "",     // frequently absent - see below
  createdTime: c.created_time
}));
Do not rely on the commenter's identity. Graph often returns from as an empty object, or omits it, for users who have not granted your app profile access. Always default it, and never key a workflow on the author's name or ID being present.

Paginating

// First pass
{ "resource": "post", "operation": "getComments",
  "postId": "1153558217851822_122099306859425226", "limit": 25, "after": "" }

// Subsequent passes
{ "resource": "post", "operation": "getComments",
  "postId": "1153558217851822_122099306859425226", "limit": 25,
  "after": "{{ $output.previousPage.items[0].nextCursor }}" }

Stop when nextCursor is "" or count is 0.

Notes and Cautions

  • Hidden comments still appear. A comment hidden with moderation/hideComment remains readable through the API. Deduplicate against what you have already actioned, or a polling workflow will hide the same comment repeatedly.
  • Replies are comments too. To read replies to a comment, pass that comment's ID as postId. Top-level results do not include nested replies.
  • Token validation is lighter here — non-blank only, not the 100-character minimum.
  • Comment text is user-generated content. Treat it as untrusted: escape it before rendering, and never pass it unchecked into a downstream command or prompt.
