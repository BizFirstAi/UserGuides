page/getInsights

Retrieve Facebook Page analytics metrics for a given aggregation period. Returns the raw Graph insights response.

Palette name: Get Facebook Page Insights  ·  Graph call: GET /{pageId}/insights  ·  Permissions: read_insights + pages_read_engagement  ·  Field reference: Page Operations
Leave the Metric field blank unless you know the metric is current. The properties panel suggests page_impressions in its placeholder and help text. That metric is deprecated for newer Pages and returns (#100) valid insights metric required. Blank is the reliable choice — the node then requests page_impressions_unique,page_post_engagements, which work on all v25.0 Pages.

When to Use

  • Scheduled reporting. Pull daily metrics into a warehouse or spreadsheet for dashboards.
  • Engagement alerting. Notify a channel when engagement drops below a threshold.
  • Campaign measurement. Sample metrics before and after a push to quantify its effect.
  • Executive summaries assembled weekly from several sources, of which the Page is one.

Configuration

FieldRequiredDescription
resourceRequiredMust be page.
operationRequiredMust be getInsights.
pageAccessTokenRequiredPage access token, or a stored credential.
pageIdRequiredNumeric Page ID.
metricOptionalComma-separated metric names. Blank applies page_impressions_unique,page_post_engagements.
periodOptionalAggregation window: day, week, month, or lifetime. Blank applies day.
The form marks Metric as required; the node does not. The properties panel shows a required marker on Metric, but the operation treats it as optional and substitutes the defaults above when it is blank. If the panel will not let you save with it empty, enter page_impressions_unique,page_post_engagements explicitly — that is what the node would have used anyway.

The result limit is fixed at 100 and is not configurable.

Sample Configuration

{
  "resource": "page",
  "operation": "getInsights",
  "credentialID": 4021,
  "pageId": "1153558217851822"
}

With explicit metrics and a weekly window:

{
  "resource": "page",
  "operation": "getInsights",
  "credentialID": 4021,
  "pageId": "1153558217851822",
  "metric": "page_impressions_unique,page_post_engagements",
  "period": "week"
}

Output

FieldTypeDescription
statusstring"success"
items[0].datastringThe entire Graph insights response, serialised as JSON text. "[]" when empty.
data is a string and there is no count. Unlike the paginated list operations, this one emits no item count and no cursor. Parse the string downstream before reading any values out of it. 
{
  "status": "success",
  "resource": "page",
  "operation": "getInsights",
  "items": [
    {
      "data": "{\"data\":[{\"name\":\"page_impressions_unique\",\"period\":\"day\",\"values\":[{\"value\":128,\"end_time\":\"2026-08-20T07:00:00+0000\"}]}]}"
    }
  ]
}

Reading a value out

const raw     = $input.items[0].data;
const parsed  = JSON.parse(raw);

return parsed.data.map(metric => ({
  name:   metric.name,
  period: metric.period,
  latest: metric.values?.[metric.values.length - 1]?.value ?? 0
}));

Deprecated Metrics

MetricStatus
page_impressionsDeprecated for newer Pages. Returns (#100) valid insights metric required.
page_engaged_usersDeprecated for newer Pages. Same error.
page_impressions_uniqueCurrent. Part of the node's default set.
page_post_engagementsCurrent. Part of the node's default set.

Meta retires and replaces insights metrics regularly. Before adding a metric name to a production workflow, confirm it against the current Graph API reference — a metric that worked last year may not work now.

Notes and Cautions

  • New Pages return sparse or empty data. Insights need traffic. A test Page with no audience legitimately returns empty value arrays — that is not a failure.
  • Insights lag. Facebook aggregates on its own schedule; today's numbers may be incomplete. Report on completed periods rather than the current one.
  • Token validation is lighter here — non-blank only, not the 100-character minimum.
  • read_insights is a separate permission from the rest of the node. A token that works everywhere else will fail here if that scope is missing.
