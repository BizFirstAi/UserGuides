Input & Output

The data contract: what the node reads, the success envelope every operation shares, per-operation output fields, and how failures reach the error port.

Input

The node has one input port, main. It does not read values out of the incoming payload — every value comes from node configuration. Upstream data reaches the node only through expressions written into configuration fields.

{
  "resource": "post",
  "operation": "comment",
  "postId": "{{ $output.publishStep.items[0].postId }}",
  "message": "{{ $output.draftReply.items[0].text }}"
}

Output Ports

PortLabelFires when
mainSuccessThe Graph call succeeded and the response parsed.
errorErrorAnything else — validation, authentication, Graph error, timeout, or an unexpected exception.
The node never throws. Every failure path is caught and routed to the error port. If you want to see a failure on the canvas rather than silently stopping the branch, wire the error port to something — a notification, a Catch Block, or a logging step.

The Success Envelope

All 14 operations emit the same four top-level keys:

{
  "status":    "success",
  "resource":  "<resource>",
  "operation": "<operation>",
  "items":     [ { ...operation-specific fields... } ]
}

The three paginated operations add one more key at the top level:

OperationExtra key
page/getFeedcount — number of posts in this page of results
post/getCommentscount — number of comments
message/getConversationscount — number of conversations
items always has exactly one element. Even for list operations. The node does not fan a Graph collection out into one item per record — it puts the entire raw response into a single field, as a JSON string. Read the next section before building anything that iterates.

List Operations Return Strings

Four operations put Facebook's entire JSON response into a single string field:

OperationField holding the raw JSON
page/getFeeditems[0].posts
post/getCommentsitems[0].comments
message/getConversationsitems[0].conversations
page/getInsightsitems[0].data

Each is "[]" when there is nothing to return. Parse before use:

const raw    = $input.items[0].posts;
const parsed = JSON.parse(raw);

// parsed.data          -> the array of records
// parsed.paging.cursors -> before / after cursors

return parsed.data.map(post => ({
  postId:      post.id,
  message:     post.message ?? "",
  createdTime: post.created_time
}));

Place a Function, Code Execute, or JSON Transform node immediately after any of the four, so the rest of the workflow works with normal rows.

Five Rules That Hold Everywhere

RuleConsequence
Missing means empty, not absentA field Facebook did not return is emitted as "", or 0 for numbers, or "[]" for the JSON-string fields. Keys are never dropped, so about: "" on a fresh Page is normal.
Timestamps are localcreatedTime and updatedTime are generated by the node when the call succeeded, not read from Facebook. They approximate the publish time.
permalink is always emptyBoth media operations declare the field but never populate it. Build a URL from mediaId if you need a link.
Casing is normalisedGraph's fan_count becomes fanCount. Graph's file_url corresponds to the videoUrl config key. Do not assume Graph field names carry through.
Boolean result fields carry no informationsuccess on post/update, deleted on deleteComment, and isHidden on hideComment are always the requested value on the success port. Branch on the port, not on these.

One Field Worth Special Care

message/send often returns an empty messageId on success. Facebook does not reliably return a message ID for that endpoint, and the node emits "" rather than omitting the field. A workflow that treats a blank messageId as failure will report false negatives. Use the success port as the signal instead.

Error Output

The error port carries a code, a message, and where available the raw Graph response body.

{
  "status": "error",
  "errorCode": "FACEBOOK_AUTH_ERROR",
  "errorMessage": "Invalid access token"
}

Codes fall into three groups:

GroupMeaning
Local validation, e.g. FACEBOOK_VALIDATION_ERRORRejected before any request was sent. Nothing reached Facebook.
Graph errors, e.g. FACEBOOK_API_ERROR, FACEBOOK_PERMISSION_ERRORFacebook refused the call. The real explanation is in the raw response.
Transport, e.g. FACEBOOK_TIMEOUT, FACEBOOK_REQUEST_ERRORThe request did not complete. Network, DNS, TLS, or timeout.

Two failures produce their own messages rather than a code:

  • No token at all — pageAccessToken is required. Set credentialID in the node config or provide pageAccessToken inline.
  • Cancellation or an unexpected exception — a sentence naming the operation and the identifier involved.

Declared Schema Versus Actual Output

The node's registered output schema advertises generic keys — result, data, error, pagination. The runtime output is what this page documents: status, resource, operation, items, and sometimes count. Build against the runtime shape. If a design-time helper offers the generic keys, ignore them.
