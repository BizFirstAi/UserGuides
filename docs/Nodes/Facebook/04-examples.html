Examples

Six complete workflows — scheduled publishing, post-and-comment, comment moderation, Messenger auto-acknowledge, publishing a generated image, and a weekly performance snapshot.

Five complete workflows. Each names the nodes in order, gives the Facebook node configuration, and calls out the part people usually get wrong.

All examples assume a stored credential, referenced as credentialID. Replace the numeric IDs with your own. See Authentication.

Example 1 — Publish a Scheduled Post

Nodes: Scheduled Trigger → Facebook page/post → Variable Assignment

The simplest useful workflow. A schedule fires, the node publishes, and the resulting post ID is stored so later steps can act on it.

// Facebook node
{
  "resource": "page",
  "operation": "post",
  "credentialID": 4021,
  "pageId": "{{ $env.FB_PAGE_ID }}",
  "message": "{{ $env.WEEKLY_ANNOUNCEMENT }}",
  "link": "https://yourbrand.com/whats-new"
}

// Variable Assignment - keep the ID for the rest of the run
lastPostId = {{ $output.publish.items[0].postId }}
Wire the error port. Without it, a failed publish stops that branch silently and the schedule simply appears not to have run. Route it to a notification so someone finds out.

Example 2 — Publish, Then Add a Source Comment

Nodes: Manual Trigger → Facebook page/post → Facebook post/comment

Keeps the post body clean while still publishing links, disclaimers, or citations. The second node consumes the first node's postId directly.

// Node 1 - publish
{
  "resource": "page",
  "operation": "post",
  "credentialID": 4021,
  "pageId": "1153558217851822",
  "message": "Our Q3 sustainability report is out."
}

// Node 2 - comment, using Node 1's output
{
  "resource": "post",
  "operation": "comment",
  "credentialID": 4021,
  "postId": "{{ $output.publish.items[0].postId }}",
  "message": "Full report and methodology: https://yourbrand.com/sustainability-q3"
}

Connect node 1's Success port to node 2. If the publish fails there is no post ID, and the comment must not run.

Example 3 — Comment Moderation Loop

Nodes: Scheduled Trigger → Facebook post/getComments → Function (parse) → Loop → If Condition → Facebook moderation/hideComment

The standard shape for automated moderation. Note the parse step — it is required, not optional.

// Node 2 - read comments
{
  "resource": "post",
  "operation": "getComments",
  "credentialID": 4021,
  "postId": "{{ $var.watchedPostId }}",
  "limit": 50
}
// Node 3 - Function: turn the JSON string into rows
const raw    = $input.items[0].comments;
const parsed = JSON.parse(raw);
const seen   = $var.actionedCommentIds ?? [];

return parsed.data
  .filter(c => !seen.includes(c.id))          // skip what we already handled
  .map(c => ({
    commentId: c.id,
    message:   (c.message ?? "").toLowerCase()
  }));
// Node 5 - If Condition
{{ $item.message.includes("http://") || $item.message.includes("free crypto") }}

// Node 6 - hide on the true branch
{
  "resource": "moderation",
  "operation": "hideComment",
  "credentialID": 4021,
  "commentId": "{{ $item.commentId }}",
  "isHidden": true
}
Hidden comments still come back from the API. Without the seen filter above, every scheduled run re-hides the same comments and burns quota doing it. Persist the actioned IDs in a workflow variable or a database table.

Prefer hiding to deleting here. If a keyword rule misfires, hiding is reversible — deletion is not.

Example 4 — Messenger Auto-Acknowledge

Nodes: Scheduled Trigger → Facebook message/getConversations → Function (parse) → Loop → If Condition → Facebook message/send

Because there is no Facebook trigger, new messages are found by polling. Poll often enough to stay inside the 24-hour reply window — every 15 minutes is a reasonable starting point.

// Node 2 - list conversations
{
  "resource": "message",
  "operation": "getConversations",
  "credentialID": 4021,
  "pageId": "1153558217851822",
  "limit": 25
}
// Node 3 - Function: parse and find threads needing a reply
const parsed  = JSON.parse($input.items[0].conversations);
const replied = $var.acknowledgedThreads ?? [];

return parsed.data
  .filter(t => !replied.includes(t.id))
  .map(t => ({
    conversationId: t.id,
    updatedTime:    t.updated_time
  }));
// Node 6 - send the acknowledgement
{
  "resource": "message",
  "operation": "send",
  "credentialID": 4021,
  "recipientId": "{{ $item.psid }}",
  "messageText": "Thanks for your message. An agent will reply within one business hour."
}
Two things break this workflow if ignored. The recipient must be a PSID, which only exists after the user messages the Page — and the reply must land inside the 24-hour window from their last message. Outside it, Facebook refuses the send on policy grounds. See message/send.

Example 5 — Publish a Generated Image

Nodes: Scheduled Trigger → Code Execute (render chart) → S3 (upload, public) → Facebook media/uploadImage

The node cannot upload binary content — Facebook fetches the URL itself. Anything generated in the workflow must be staged on a public host first.

// Node 4 - publish the staged image
{
  "resource": "media",
  "operation": "uploadImage",
  "credentialID": 4021,
  "pageId": "1153558217851822",
  "imageUrl": "{{ $output.s3Upload.items[0].publicUrl }}",
  "caption": "This week's performance summary"
}
The URL must be reachable by Facebook's servers, not just by yours. A presigned URL that expires in five minutes, a VPN-only host, or a bucket requiring authentication will all fail — and the node's local check only validates the URL's shape, so the failure appears as a Graph error rather than a validation error.

For video, the same shape applies with media/uploadVideo — but add a Delay and an HTTP Request node afterwards to poll GET /{mediaId}?fields=status, because a successful upload only means Facebook accepted the file.

Example 6 — Weekly Page Performance Snapshot

Nodes: Scheduled Trigger (weekly) → Facebook page/getInfo → Facebook page/getInsights → Function (parse) → Email / Slack

Combines profile data and analytics into one recurring report. Two Facebook calls, then a single formatting step.

// Node 2 - follower count and Page name
{
  "resource": "page",
  "operation": "getInfo",
  "credentialID": 4021,
  "pageId": "1153558217851822"
}

// Node 3 - metrics for the week. Leave metric blank to use working defaults.
{
  "resource": "page",
  "operation": "getInsights",
  "credentialID": 4021,
  "pageId": "1153558217851822",
  "period": "week"
}
// Node 4 - Function: combine both into one summary object
const page    = $output.pageInfo.items[0];
const metrics = JSON.parse($output.pageInsights.items[0].data);

const latest = name => {
  const m = metrics.data.find(x => x.name === name);
  return m?.values?.[m.values.length - 1]?.value ?? 0;
};

return [{
  pageName:    page.name,
  followers:   page.fanCount,
  reach:       latest("page_impressions_unique"),
  engagements: latest("page_post_engagements")
}];
Leave metric blank. The properties panel suggests page_impressions, which is deprecated and returns (#100) valid insights metric required. Blank applies the node's current defaults. read_insights is also a separate permission from the rest of the node — a token that works everywhere else will fail here without it. See page/getInsights.

Report on completed periods rather than the current one — Facebook aggregates insights on its own schedule, so today's numbers are usually incomplete.

Patterns Worth Reusing

PatternWhy
Always parse before iteratingFour operations return a JSON string. A Function node immediately after them keeps the rest of the workflow normal. See Input & Output.
Track what you have actionedPolling plus a write operation without deduplication means repeating the same action forever.
Wire the error portFailures route there rather than throwing. An unwired error port is a silent failure.
Capture IDs immediatelypostId, commentId, and mediaId are the only handles on what a workflow created. Store them as they come back.
Check before retrying a writeThe automatic retry on 429 and 5xx re-sends the body, so a call that appeared to fail may have succeeded. Read the Page before re-running.
Gate irreversible stepsPut an Approval node in front of moderation/deleteComment.
