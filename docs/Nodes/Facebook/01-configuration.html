Configuration

Every configuration key the Facebook node reads, its type, default, and which operations use it — plus the identifier formats and field limits that cause most setup problems.

Every operation is configured on one node. The resource and operation pair selects which behaviour runs; the remaining keys are whatever that pair needs. Selecting an operation in the properties panel loads the matching form.

How Configuration Is Read

Each operation reads a fixed, named set of config keys. Three rules follow from that, and they explain most configuration problems:

  • Spelling and case matter. Keys are read by exact name. An unrecognised key is ignored silently — no warning, no error.
  • A missing key arrives as an empty string, never as null. The node treats blank and absent identically.
  • Whitespace is trimmed, not rejected. A trailing space on a Page ID is removed before the request is built.

Routing Keys

KeyTypeAccepted values
resourceenumpage, post, message, reactions, moderation, media
operationenumpost, getFeed, getInfo, getInsights, comment, getComments, update, send, getConversations, add, hideComment, deleteComment, uploadImage, uploadVideo
Operation names are camelCase and matched exactly. getFeed routes. getfeed, GetFeed, and get-feed do not — they fall through to an unsupported-operation error. Note that the properties panel subtitle displays kebab-case, for example page / get-feed. That is a display label. The value written to configuration is getFeed.

The Instagram and WhatsApp nodes genuinely use kebab-case operation names, so configuration copied from those nodes will not route here.

Blank Optional Fields Are Removed

An optional field left empty is dropped from the outgoing request rather than sent as an empty value. This is deliberate: Facebook rejects a post carrying an empty picture with (#100) Only owners of the URL have the ability to specify the picture, even though the field is logically absent.

Practical consequence: you never need to remove an unused optional field from a configuration. Leaving link, picture, and caption blank is exactly equivalent to omitting them.

Complete Example

{
  "resource": "page",
  "operation": "post",
  "credentialID": 4021,
  "pageId": "1153558217851822",
  "message": "QA smoke test from Flow Studio",
  "link": "",
  "picture": "",
  "caption": ""
}

{
  "resource": "page",
  "operation": "post",
  "credentialID": 4021,
  "pageId": "1153558217851822",
