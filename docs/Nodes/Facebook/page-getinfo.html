page/getInfo

Read a Facebook Page profile: ID, name, about text, category, and follower count. The smallest operation in the node, and the best first test of a new token.

Palette name: Get Facebook Page Info  ·  Graph call: GET /{pageId}?fields=id,name,about,category,fan_count  ·  Permissions: pages_read_engagement  ·  Field reference: Page Operations
Start here when testing a new token. This is the smallest, safest operation in the node — two inputs, read-only, nothing published. If your token and Page ID are correct, this succeeds. If it fails, the problem is the credential, not the workflow.

When to Use

  • Verify a credential before wiring up any write operation.
  • Track follower growth. Record fanCount on a schedule into a database or spreadsheet.
  • Resolve a Page name for use in notification text, so alerts read "QA Test Page" rather than a numeric ID.
  • Health check. A scheduled run that alerts when the Page becomes unreachable, which usually means the token was revoked.

Configuration

FieldRequiredDescription
resourceRequiredMust be page.
operationRequiredMust be getInfo.
pageAccessTokenRequiredPage access token, or a stored credential.
pageIdRequiredNumeric Page ID, at most 50 characters.

The fields requested from Graph are fixed: id, name, about, category, fan_count. There is no field-selection option.

Sample Configuration

{
  "resource": "page",
  "operation": "getInfo",
  "credentialID": 4021,
  "pageId": "1153558217851822"
}

Output

FieldTypeDescription
statusstring"success"
items[0].idstringPage ID.
items[0].namestringPage display name.
items[0].aboutstringShort description. "" when the Page has none.
items[0].categorystringFacebook's category, e.g. Software company.
items[0].fanCountnumberFollower count. 0 on a new Page.
{
  "status": "success",
  "resource": "page",
  "operation": "getInfo",
  "items": [
    {
      "id": "1153558217851822",
      "name": "QA Test Page - Anjaly",
      "about": "",
      "category": "Software company",
      "fanCount": 0
    }
  ]
}
Empty is not missing. Graph returns fan_count; the node emits fanCount. Fields absent from Facebook's response are emitted as "" — or 0 for fanCount — never omitted. An empty about on a fresh Page is normal, not a failure.

Notes and Cautions

  • Token validation is lighter here. Only a non-blank check runs, not the 100-character minimum some write operations enforce. A short junk token therefore reaches Facebook and returns (#190) instead of failing locally — the same bad input produces a different error on page/post.
  • A (#100) Unsupported get request almost always means a User token. This operation is where that mistake usually surfaces first. Confirm "type": "PAGE" with debug_token. See Authentication.
  • Read-only and idempotent. Safe to run as often as quota allows.
