page/getFeed

List posts from a Facebook Page feed with cursor pagination. Returns the raw Graph response and a cursor for the next page.

Palette name: Get Facebook Page Feed  ·  Graph call: GET /{pageId}/feed  ·  Permissions: pages_read_engagement  ·  Field reference: Page Operations

When to Use

  • Poll for new posts. With no Facebook trigger available, a Scheduled Trigger plus this node is how a workflow notices Page activity.
  • Archive Page content into a database or data lake on a nightly schedule.
  • Feed a moderation loop. List recent posts, then read each post's comments with post/getComments.
  • Confirm a publish. Read the feed after page/post to verify the post landed.

Walkthrough

1Place the node

2Configure

The breadcrumb reads page / get-feed. Only the token and Page ID are required; Limit defaults to 25 and After Cursor is left blank on the first call.

3Run

Configuration

FieldRequiredDescription
resourceRequiredMust be page.
operationRequiredMust be getFeed.
pageAccessTokenRequiredPage access token, or a stored credential.
pageIdRequiredNumeric Page ID.
limitOptionalPosts per page. Defaults to 25.
afterOptionalPagination cursor from a previous run's nextCursor. Blank fetches the first page.

Fields requested from Graph are fixed: id, message, created_time. They are not configurable.

Output

FieldTypeDescription
statusstring"success"
countnumberNumber of posts in this page of results. Top level, beside status.
items[0].postsstringThe entire Graph response, serialised as JSON text. "[]" when empty.
items[0].nextCursorstringCursor for the next page, or "" when there are no more results.
posts is a string, not an array. The node returns one item whose posts field holds the raw Graph JSON as text. It does not emit one item per post. Parse it downstream with a JSON Transform, Function, or Code Execute node before iterating.

      "nextCursor": "QVFIUm..."
    }
  ]
}

Paginating Through the Feed

Wrap the node in a Loop. On each pass, feed the previous run's cursor back into after and stop when it comes back empty.

// First pass
{ "resource": "page", "operation": "getFeed",
  "pageId": "1153558217851822", "limit": 25, "after": "" }

// Subsequent passes
{ "resource": "page", "operation": "getFeed",
  "pageId": "1153558217851822", "limit": 25,
  "after": "{{ $output.previousPage.items[0].nextCursor }}" }

Exit condition: nextCursor is "", or count is 0.

Notes and Cautions

  • Token validation is lighter here. Unlike page/post, this operation only checks that the token is non-blank — it does not enforce the 100-character minimum. A short junk token therefore reaches Facebook and returns (#190) rather than failing locally.
  • The type field is deliberately not requested. Graph returns (#12) deprecate_post_aggregated_fields_for_attachement when it appears in the field list, so it was removed.
  • Polling costs quota. Each run consumes a Graph API call against the Page's hourly allowance. Poll at the slowest interval the use case tolerates. See Rate Limits.
