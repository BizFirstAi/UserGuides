moderation/hideComment

Hide a comment from the public view of a post, or unhide it again. Reversible, and the recommended default for automated moderation.

Palette name: Hide Facebook Comment  ·  Graph call: POST /{commentId} with body {"is_hidden": true|false}  ·  Permissions: pages_manage_engagement  ·  Field reference: Moderation
This is the right default for automated moderation. Hiding is reversible and quiet: the comment disappears from the public view of the post but stays visible to its author and their friends, so there is no notification and no visible deletion. If a screening rule misfires, you can undo it. Prefer this over moderation/deleteComment unless the content is clearly abusive.

When to Use

  • Keyword screening. Hide comments containing spam markers, competitor links, or blocked terms.
  • Out-of-hours holding. Hide new comments on a sensitive post until a moderator reviews them, then unhide the acceptable ones.
  • Unhide after review. The same operation with isHidden: false restores a comment.
  • Campaign hygiene. Keep a promotional thread free of off-topic replies without deleting anyone's contribution.

Hide and Unhide Are One Operation

The Hide Comment switch in the properties panel maps to isHidden. It defaults to true — omitting the key hides the comment. Set it to false to unhide.

isHiddenEffect
true, or omittedComment is hidden from public view.
falseComment is restored to public view.

The node deliberately sends the is_hidden body parameter rather than the legacy ?method=hide query form, because the legacy form could only ever hide — never unhide.

Configuration

FieldRequiredDescription
resourceRequiredMust be moderation.
operationRequiredMust be hideComment.
pageAccessTokenRequiredPage access token, or a stored credential. Minimum 100 characters.
commentIdRequiredThe comment to hide or unhide. Returned by post/comment as commentId, or found inside post/getComments.
isHiddenOptionalBoolean. Defaults to true.

This operation does not read pageId — the comment ID identifies the target.

Sample Configuration

{
  "resource": "moderation",
  "operation": "hideComment",
  "credentialID": 4021,
  "commentId": "122099783774252226_966580579776255",
  "isHidden": true
}

Unhiding after a moderator approves:

{
  "resource": "moderation",
  "operation": "hideComment",
  "credentialID": 4021,
  "commentId": "{{ $output.approvalStep.items[0].commentId }}",
  "isHidden": false
}

Validation

MessageCause
Invalid access tokenToken blank or shorter than 100 characters.

FACEBOOK_NOT_FOUNDComment does not exist, was deleted, or the token cannot see it.

Notes and Cautions

  • Idempotent. Hiding an already-hidden comment leaves it hidden. Safe to retry, and safe to run over a batch that may include comments you have already actioned.
  • Hidden comments still come back from the API. post/getComments returns them, so a naive polling loop will keep re-hiding the same comment. Track actioned comment IDs in a variable or database.
  • The author can still see their comment, as can their friends. Hiding is not the same as removing, and a determined commenter may notice their reply no longer appears for others.
  • Automated moderation deserves an audit trail. Log which comment was hidden and which rule matched, so a human can review and reverse decisions.
  • Comment text is untrusted input. Screen it carefully, and escape it before rendering it anywhere.
