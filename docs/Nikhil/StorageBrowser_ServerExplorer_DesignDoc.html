Project 1 · Storage Browser
01

Overview

What it is: A standalone web app for browsing BizFirst MinIO storage servers. Any authenticated user can log in, register MinIO servers, and browse their buckets and objects — with a cleaner, more usable experience than the MinIO Console.

This is Project 1 — intentionally scoped small. The MinIO Console open-source UI is the design reference. The goal is to copy that project, strip out the complexity, and rebuild it using BizFirst in-house packages. Estimated build time: 2–4 hours once the project is scaffolded.

Once Project 1 is done, it becomes the foundation for Project 2 (Server Explorer), which extends it to cover all BizFirst infrastructure servers — not just MinIO.

04

Features

Auth — Login & Account Creation

Any user can create an account or log in. Uses src/passport/. No role restrictions in Phase 1.

Server Registration

Users add MinIO servers by entering: display name, endpoint URL, access key, secret key. Servers persist per account. Remove a server at any time.

Object Browser

Two-panel layout: left shows bucket list for the selected server, right shows objects within the selected bucket with folder-style navigation and breadcrumbs. Read-only in Phase 1.

Project 2 · Server Explorer
06

Overview

What it is: An extension of the Storage Browser into a full infrastructure management UI. Not just MinIO — every BizFirst server type (primary, backup, retention, chat engine, etc.) is visible, queryable, and eventually controllable from one place.

Project 2 starts after Project 1 is complete and approved. The Storage Browser codebase is moved into a new module called server-explorer and extended. This is a multi-tenant product — every company manages their own servers here.

Phase 1 of Project 2 focuses on read-only visibility: pull each server's docker.xml config and show it to the user, along with live status. Phase 2 adds automation commands (take a backup, restart a service, etc.).

07

Features

Multi-Server Dashboard

All BizFirst infrastructure servers in one view: primary MinIO, hot standby, archival, compliance/PITR, backup server, SQL Server, chat engine — each with connection status and key metrics.

Right-Click Context Menu

Right-clicking any server card opens a context menu: View Docker Config (reads the server's docker.xml / docker-compose and displays it in a read-only panel) and Query Live Data (fetches live stats: uptime, storage used, replication health, active connections).

Automation (Phase 2)

Action commands per server: trigger a backup, run a health check, restart a container. This is where the "beautiful UI to manage servers" becomes actionable. Individual actions are the building blocks — automation chains these actions later.

Tenant Management

Each company (tenant) manages their own set of registered servers. Isolated per account with proper auth boundaries.

08

Phases

Phase 1
Read + Visibility
  • Extend Storage Browser into server-explorer module
  • Add all server types to the dashboard (not just MinIO)
  • Right-click: read and display docker.xml config
  • Right-click: query and display live server data
Phase 2
Automation
  • Action commands per server (backup, restart, health check)
  • Tenant management — per-company server isolation
  • Audit log of all actions taken
Phase 3
Flow Studio Integration
  • Server Explorer embeds as a panel inside Flow Studio
  • Workflow nodes can trigger server actions directly
  • Observability data surfaces in Flow Studio dashboards
09

Flow Studio Integration

Both projects ultimately integrate into Flow Studio. Storage Browser adds storage objects as first-class references in workflow steps. Server Explorer adds infrastructure actions as workflow nodes — so an AI workflow can say "take a backup of SQL Server" and Server Explorer executes it.

Note: Integration is Phase 3 of Project 2 and does not block either project's Phase 1 build.

10

Open Questions for Binoy

  1. Should MinIO server credentials (access key / secret) be stored per-user or shared org-wide? Per-user is more secure but adds setup friction for teams.
  2. Is there an existing BizFirst backend service to proxy minio-js calls through, or should Storage Browser include its own lightweight API layer?
  3. How is each server's docker.xml located — is there a registry or file path convention, or does the user paste it in when registering the server?
  4. For the mobile app conversion (Phase 2 of Project 1) — is this React Native wrapping the same API, or a separate native codebase?
  5. Which server types should be pre-registered in Server Explorer (Phase 1) vs. user-added — should the MinIO stack servers come pre-loaded from the docker-compose?
