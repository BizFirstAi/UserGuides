Searching Templates

The Jobs screen is where you find every template you have access to, run one instantly, or jump into its editor. It remembers how you last searched it, so you're never starting from a blank list.

Opening Jobs

Jobs is a left-menu entry. Click it and you land on a searchable grid of every template your account can see — across every workflow and every app in your tenant, not just the one you happen to be working in.

The Grid

Each row is one template, showing:

  • Name and Description — whatever was set on the Basics tab
  • Scope — a resolved label showing what it targets, e.g. "Node — Send Invoice Email"
  • Last Executed — when it was last run
  • Execution Count — how many times it's been run in total
  • Enabled — whether it's currently allowed to run
  • Concurrency Behavior — Allow or Block, at a glance, without opening the editor

Use the search box and filters above the grid to narrow this down by name, scope, or enabled state, and click any column header to sort.

Your Search Is Remembered

Every field you set on this screen — your search text, the scope filter, the enabled/disabled filter, and the sort column — is saved automatically as you use it, per user. The next time you open Jobs, you land right back on the same search instead of an empty screen you have to set up again. This is entirely local to your own account; it doesn't change what anyone else sees when they open Jobs.

Row Actions

Action What It Does
Execute Runs the template immediately, right from the row — no navigation. See Executing a Template for what happens next, including the Concurrency Behavior check.
Config Opens the full five-tab editor for that template — the same editor covered in The Five Tabs — so you can review or change its data.
Tip: If you're not sure whether a template is safe to run twice in a row, check its Concurrency Behavior column before clicking Execute — Block means a second click while the first run is still going will be rejected, not silently queued.
