Agents Directory

Base route: api/v1/realestate/agents — not a CRM contact record

This is a local directory, not a CRM. Agent is intentionally minimal and does not duplicate a CRM's contact model (e.g. Odoo's res.partner). It exists purely to attribute a listing to a real-estate agent. It is also distinct from the ExternalProvider/ExternalRecordID mechanism, which links a property — not an agent — to an external CRM record.

The three-way matching model

When a listing is imported from a feed, three distinct pieces of agent data can exist at once:

FieldOwnerMeaning
Property.ListAgentIDPropertyThe only real relational link — FK to a matched local Agent row. Null until matched.
Property.ListAgentName / ListAgentMlsId / ListOfficeNamePropertyRaw values captured from the source feed at import time. Kept even after matching — they record what the feed said at that point in time and may drift from the agent's current canonical data.
Agent.MlsIdAgentThe agent's own canonical, current MLS id. Matching compares the raw ListAgentMlsId against this canonical value.
Agent.MlsId is indexed but NOT unique in the database, so a lookup by MlsId can legitimately return more than one row — matching code must handle that rather than assume a single result.

Matching

RouteNotes
POST /matchResolves a listing's raw feed agent values to a local agent row, optionally creating one. The response reports whether the match was ambiguous rather than hiding it — see Troubleshooting.

Once matched, attribute the listing with the Properties API's PATCH /listing-agent (see Properties API) — it sets ListAgentID only; the raw feed values are deliberately left untouched.
