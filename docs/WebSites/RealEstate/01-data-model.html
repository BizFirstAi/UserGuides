Data Model

The four core entities and how they relate.

Property — the core listing entity

Mapped from RealEstate_Properties. Owned entirely by BizFirst, not any CRM, so it stays portable across CRM providers. 40+ RESO-aligned fields; the ones worth calling out:

FieldTypeNotes
PropertyIDint, PKIdentity
MLSNumbernvarchar(50), nullableNo uniqueness constraint — repeated imports can produce duplicates
ExternalProviderID / ExternalRecordIDint? / nvarchar(255)?Link to an external CRM record. ExternalRecordID is a string since not every provider uses integer ids. See Connecting to Odoo & CRM
ListAgentIDint?, FK → AgentResolved local agent. Null until matched — see Agents Directory
ListAgentName / ListAgentMlsId / ListOfficeNamenvarchar, nullableRaw, point-in-time values captured from the source feed at import — kept even after ListAgentID is matched
PropertyTypeIDint, required, FKResidential / Commercial / Land / Industrial / Mixed-Use
PropertyCategoryIDint?, FKNullable so a draft can exist before a category is chosen. Not validated against PropertyTypeID at the DB level — see Lookups & Code Lists
ListingTypeID / ListingStatusIDint, required, FKFor Sale/Rent/Lease; Draft/Active/Pending/Sold/…
AddressLine1/2, City, StateProvince, PostalCode, Countrynvarchar, mostly requiredStandard address block
Latitude / LongitudeDECIMAL(9,6)±90 / ±180 range
ParcelNumbernvarchar(100)?Assessor's parcel number (APN) — a distinct RESO field from MLSNumber
ListPrice / OriginalListPricedecimal(18,2)?ListPrice may change over the listing's life; OriginalListPrice is never overwritten once set
RentAmount, AssociationFee + AssociationFeeFrequencydecimal? / nvarchar(20)?AssociationFeeFrequency constrained by CK_RealEstate_Properties_AssociationFeeFrequency to Monthly/Quarterly/Annually/OneTime (or null)
Bedrooms, Bathrooms, SquareFootage, LotSizeSqFt, YearBuilt, GarageSpaces, StoriesTotalvariousBathrooms is DECIMAL(3,1) to allow half-baths (2.5)
ListingContractDate, OnMarketDate, CloseDate, ExpirationDateDATETIME?RESO lifecycle dates — see Properties API for how they're set
PublicRemarksnvarchar(MAX)?Marketing copy — safe to surface to consumers
PrivateRemarksnvarchar(MAX)?Agent-only. Must never be surfaced to consumers — the entire reason this is a separate column from PublicRemarks
RawListingDataJsonnvarchar(MAX)?Full source payload for fields not modeled as columns — the long tail of RESO's 300+ field dictionary
Agent attribution carries three distinct things — don't conflate them: ListAgentID (the only real relational link, FK to Agent), ListAgentName/ListAgentMlsId/ListOfficeName (raw values from the source feed at import time, kept even after matching), and Agent.MlsId (the matched agent's own canonical, current MLS id — NOT the same field as ListAgentMlsId).

Agent — local listing-agent directory

Mapped from RealEstate_Agents. Intentionally minimal — this is NOT a CRM contact record and does not duplicate a CRM's contact model (e.g. Odoo's res.partner). Populated at runtime as agents are imported/matched, so unlike the other lookups it has no seed file.

FieldTypeNotes
AgentIDint, PKIdentity
FullNamenvarchar(200), required
MlsIdnvarchar(50)?Canonical, current MLS-assigned id. Indexed but NOT unique — a lookup can legitimately return more than one row
OfficeNamenvarchar(200)?
Email / Phonenvarchar?

PropertyMedia — photos, floor plans, tours, documents

Mapped from RealEstate_PropertyMedia. Raw bytes are never stored here — MediaCID is a content-addressed reference into BizFirst's existing CID-based object store (see BizFirstStorageAi). See Media & Features for the full field reference.

PropertyFeature — typed amenity flags

Mapped from RealEstate_PropertyFeatures. One row per feature per property (UQ_RealEstate_PropertyFeatures_PropertyID_FeatureTypeID). FeatureValue is stored as a string and interpreted per the referenced FeatureType.ValueDataType (Boolean/Text/Number). See Media & Features.
