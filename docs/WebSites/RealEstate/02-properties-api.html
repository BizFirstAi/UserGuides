Properties API

Base route: api/v1/realestate/properties

PrivateRemarks is agent-only data. Any public-facing projection built on these endpoints must strip it before it reaches a consumer.

CRUD

RouteAuthNotes
POST /listRegularUserStandard paged list
POST /by-idRegularUserSingle record fetch
POST / (Create)TenantAdmin
PUT /{id}TenantAdminRoute id must match body id
DELETE /{id}TenantAdminSoft-deletes the listing only — media/feature rows are left live
POST /delete-with-childrenTenantAdminSoft-deletes the listing AND its media/features — the DB cascade only fires on a hard delete, so this is what keeps children from being left behind and visible

Identifier queries

Both return a list, not a single record — neither field has a uniqueness constraint.

RouteFilterWhy a list
/by-mls-numberMLSNumberNo uniqueness constraint on the schema — repeated imports may have produced duplicates
/by-parcel-numberParcelNumberSame reasoning

External CRM linkage

RouteAuthNotes
/by-external-recordTenantAdminFilter: ExternalProviderID + ExternalRecordID. Returns a LIST — the pair is indexed but not unique, so more than one property can claim the same external record. An importer treating this as single-row would silently pick one.
/by-external-providerTenantAdminEvery listing linked to a given provider
/unlinkedTenantAdminListings not yet linked to any external CRM — the sync backlog
PATCH /external-linkTenantAdminLink a listing to an external record
/external-unlinkTenantAdminClear the link, returning the listing to the unlinked backlog

See Connecting to Odoo & CRM for the full addon story.

Agent attribution

RouteAuthNotes
/by-agentRegularUserFilter: ListAgentID
/unmatched-agentTenantAdminListings where a raw feed agent id is present but ListAgentID is still null — the matching backlog
PATCH /listing-agentTenantAdminSets ListAgentID only — raw feed values are deliberately left untouched

Location & search

RouteNotes
/by-cityCity + optional StateProvince
/by-postal-codePostalCode
/searchMulti-criteria consumer search — every filter optional: PropertyTypeID, PropertyCategoryID, ListingTypeID, ListingStatusID, City, StateProvince, PostalCode, MinListPrice, MaxListPrice, MinBedrooms, MinBathrooms, MinSquareFootage, MinYearBuilt

Lifecycle queries

RouteAuthNotes
/closed-betweenRegularUserFromDate/ToDate — the sold/leased report
/expiring-soonTenantAdminWithinDays (default 30) + AsOfDate. Already-expired listings excluded

Listing operations

RouteNotes
/create-listingFull listing create. Rejects a category that doesn't belong to the given property type — see Lookups & Code Lists
PATCH /classificationReclassify type + category together (they must stay paired)
PATCH /listing-statusMove to a new status. Lifecycle dates are caller-driven, not status-driven — RealEstate_ListingStatuses has no Code column, only an id and display name, so the service cannot infer OnMarketDate/CloseDate from the target status. Set them explicitly.
PATCH /list-priceChanges ListPrice. OriginalListPrice is never overwritten.
PATCH /raw-listing-dataReplaces RawListingDataJson

Authorization

JWT bearer, claim-based: realestate:read covers RegularUser routes, realestate:write/realestate:full for TenantAdmin routes (create/update/delete/link operations). Policies: RealEstateRead, RealEstateWrite, RealEstateFull.
