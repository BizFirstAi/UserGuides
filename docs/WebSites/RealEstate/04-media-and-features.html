Media & Features

Photos/documents (content-addressed) and typed amenity flags

PropertyMedia — base route api/v1/realestate/property-media

No endpoint accepts file bytes. Media is referenced by content id (MediaCID), and the file must already exist in BizFirst's CID object store before it is attached.
FieldTypeNotes
PropertyMediaIDint, PK
PropertyIDint, required, FKCascade-deletes on hard delete of the parent; soft delete (the normal path) does NOT cascade at the DB level
MediaTypeIDint, required, FKPhoto / Floor Plan / Virtual Tour / Document / Video
MediaCIDnvarchar(200), requiredContent-addressed reference — bytes live in the object store
MediaURLnvarchar(500)?Optional resolved/public URL (e.g. via a CDN gateway). A convenience, not the file's identity
DisplayOrdershort, default 0Sort order within the gallery
IsPrimarybool, default falseMarks the hero image. Not DB-constrained to one row per property — enforced in the service layer
Captionnvarchar(200)?Caption / alt text
MediaMetadataJsonnvarchar(MAX)?Dimensions, file size, MIME type, source feed's media key/timestamp, etc.
RouteNotes
CRUD: /list, /by-id, POST /, PUT /{id}, DELETE /{id}Standard
/by-propertyA property's full gallery
/by-media-typeFilter by MediaTypeID
/primaryA property's primary image. Returns a LIST — IsPrimary isn't DB-constrained to one row
/by-cid"Where is this file used?" — every media row referencing a content id
POST /attachAttaches a media row to a property (CID must already exist)
PATCH /primaryPromotes one row to primary and demotes the property's existing primary
PATCH /caption

PropertyFeature — base route api/v1/realestate/property-features

One row per feature per property, enforced by UQ_RealEstate_PropertyFeatures_PropertyID_FeatureTypeID. FeatureValue is a string, interpreted per the referenced FeatureType.ValueDataType: '1'/'0' for Boolean, free text for Text, a numeric string for Number.

Setting a feature is an upsert, not an insert. The unique constraint allows only one row per property+feature and counts soft-deleted rows. Use /set or /set-many — not the generic Create — for anything import-driven.
RouteNotes
CRUD: /list, /by-id, PUT /{id}, DELETE /{id}Standard (no generic POST create — see the upsert note above)
/by-propertyAll features on a property
/by-featureOne property + one feature type
/by-feature-typeEvery property carrying a feature, optionally filtered by value — e.g. all properties with a Pool, or GarageSpaces = 2
POST /setUpserts one feature value, validated against the feature type's declared ValueDataType
POST /set-manyUpserts several feature values for one property — the feature-checklist save
POST /removeRemoves a feature
