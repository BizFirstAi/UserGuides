Roadmap

What's built today, and what's next

✅ Built

  • Full schema: RealEstate_{Properties, Agents, PropertyMedia, PropertyFeature, PropertyTypes, PropertyCategories, ListingTypes, ListingStatuses, MediaTypes, FeatureTypes, ExternalProviders}, with the platform-standard soft-delete/audit/tenant columns and named PK_/FK_/DF_/CK_ constraints.
  • Seed data for every lookup table, including ExternalProviders pre-seeded with Odoo.
  • Full layered API: BizFirst.Ai.RealEstate.{Domain, Service, Infrastructure, Api.Base, Api} — repositories, services, and both abstract base controllers and concrete controllers for all 11 resources.
  • JWT authentication with claim-based authorization policies (realestate:read/write/full).
  • Global exception handling mapping domain exceptions to proper HTTP status codes.
  • Swagger/OpenAPI documentation, enabled in development.
  • A dedicated test project (BizFirst.Ai.RealEstate.Tests) covering controller contracts, repository behavior, and service logic (Agent/catalog, PropertyFeature, PropertyMedia, Property).
  • Rich domain-model documentation baked directly into the entity source as XML doc comments — this guide is drawn from it.

⏳ Not yet built

  • No frontend/UI. This repo currently ships API + DB only — there is no src/ui equivalent to the object-browser/server-browser apps built for other BizFirst products.
  • No automated MLS/feed import pipeline. The API supports creating and updating listings (including the raw-feed agent fields and RawListingDataJson escape hatch), but the actual "pull a feed, map it, call this API" import job lives outside this repo, if it exists yet.
  • No status-driven lifecycle-date stamping. RealEstate_ListingStatuses has no stable Code column, so OnMarketDate/CloseDate stay caller-driven rather than inferred from the target status. Adding this needs a schema change first — see Troubleshooting.
  • Odoo sync is one-directional and manual today. RealEstate stores the ExternalProviderID/ExternalRecordID pointer, but nothing in this repo automatically keeps a linked Odoo record and a Property in sync — that orchestration is expected to live in a Flow Studio workflow built on the Odoo node, not in RealEstate itself.
  • Only one ExternalProvider is seeded. Twenty and EspoCRM are named in the schema's own design notes as intended future providers, but have no seed row or integration built yet.
